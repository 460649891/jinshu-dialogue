# 文档规范

本规范适用于维护本仓库的公开文档、Issue 模板、PR 说明和 Release 说明。默认使用简体中文，代码标识和上游许可保留原文。

## 文档分工

| 文档 | 读者与内容 |
| --- | --- |
| README | 用户入口：功能、下载、快速使用、支持范围、常见问题和文档导航 |
| CONTRIBUTING | 贡献者：提交范围、PR 信息和验证要求 |
| SECURITY | 漏洞报告渠道与必要信息 |
| CHANGELOG | 按版本记录用户可见的新增、修复和变化 |
| `docs/architecture.md` | 实现原理、线程与数据流、关键设计理由 |
| `docs/development.md` | 从环境配置到测试、调试的操作步骤 |
| `docs/compatibility.md` | 游戏版本证据、已知边界和适配方法 |
| `docs/releasing.md` | 构建、验收、打标签与发布操作 |

## 格式与写法

- UTF-8 编码，使用仓库 `.editorconfig` 和 `.gitattributes`。每篇文档一个一级标题，标题层级连续；列表、表格、代码块前后保留空行。
- 文档内链接使用相对于当前文件的路径；仓库、下载和上游资料使用完整 HTTPS 地址。不要提交本机绝对路径。
- PowerShell 示例从仓库根目录执行，使用占位目录，提供可直接复制的完整命令。依赖、版本和文件名与实现保持一致。
- 日期使用 `YYYY-MM-DD`，发布标签使用 `vMAJOR.MINOR.PATCH`，更新记录保留 Unreleased。不要提前填写尚未发布版本的下载结论。
- 说明具体行为和限制，区分自动测试、人工界面检查与游戏实测。性能数据必须说明测量方式；不承诺没有验证的兼容性或零丢失。
- 截图和示例使用原创内容，提交前检查人物、路径、账号和剪贴板等私人信息。上游许可、版权和来源链接不得随意改写。

## 与变更同步

操作流程变化更新 README；实现边界变化更新架构说明；支持版本变化更新兼容文档；构建或依赖变化更新发布流程与第三方声明。用户可见的变化还应加入 CHANGELOG。

新增公开文档或模板时，将文件加入 `scripts/package_source.py` 的允许清单。需要随免安装包阅读的文档，也应加入 `scripts/build.ps1` 的复制清单，确保仓库、源码包和发行包的链接完整。

提交前运行 `python scripts/check_docs.py`。该检查验证允许清单中的 Markdown 本地链接和标题锚点；外部页面、代码示例能否执行，以及截图内容仍需人工核对。
