# 采集与桌面界面

项目只适配 `profiles/jshyl-5.60c.json` 中的主程序，监听过程不改写游戏文件或存档。Frida 的 `Interceptor` 会临时改动进程内的入口指令以安装钩子，停止采集后解除连接。因此这里的“读取对白”不等于完全不改变进程内存。

## 一条对白如何到达界面

```text
游戏写入新人物编号 → 替换完整正文 → 正文赋值返回
  → 从同一对象读取正文及人物编号 → 解码人物姓名 → 分配 sequence
  → 一条包含 speaker + text 的原子事件
  → Frida 回调放入有界队列
  → Python 按 GB18030 解码、按 session/sequence 去重
  → 刷新 TXT + JSONL 文件 → Qt 信号 → 每 100 ms 批量更新列表
```

可以把它理解为 Java 中的事件生产者、`BlockingQueue`、后台消费者和 UI 线程。Frida 回调只入队，不负责磁盘或界面；队列满时明确停止并报错，避免阻塞游戏线程或悄悄丢记录。文件按次创建，不覆盖已有记录。每条写入后 flush；这降低异常退出时的丢失范围，不代表已经执行磁盘 fsync。

`src/capture.py` 提供 `CaptureService.run(stop_event, on_status, on_dialogue)`。`src/dialogue.py` 不依赖 Qt 或 Frida，负责转换和持久化；`src/gui.py` 中的工作线程负责启动采集、发信号及响应停止。停止信号通过 Frida Cancellable 取消等待中的调用。窗口关闭时先等待采集结束，不销毁仍在运行的 QThread。

## 去重与人物配对

画面重绘次数不能代表新对白数量；对 `(人物名, 文字)` 永久去重又会误删剧情中确实重复的一句。当前实现以正文赋值完成作为边界，每次提交分配递增序号并输出一次；重绘不触发该位置，下一次提交即使文字相同也会输出。

游戏会先更新人物编号，中间可能绘制窗口，之后才替换正文。v0.2 的绘制缓存可能在这个间隙拼接不同轮次的内容。v0.3 监听字符串赋值函数，用调用返回位置筛选正文赋值，在该函数返回时同步读取目标对白对象、完整正文、人物编号及对应姓名。短函数返回后即结束本次钩子，不把等待玩家点击的整段对白函数作为活跃调用。姓名表指针和字符的解码只读取内存，不调用游戏函数或写入人物数据。负人物编号输出空姓名，由宿主显示“未知人物”；异常编号明确报错，绝不复用上一人物。

这一回调返回前游戏线程停在提交位置，因此姓名与正文被复制成同一条事件，再交给队列处理。重连后更换会话标识。启动时已显示的对白可能已经越过提交点，因此从下一句开始采集。Node 测试执行实际 agent，模拟外部进程内存及非恒等的姓名解码表，验证 1,000 次快速切换和连续同文。

适配配置包含 SHA-256、函数相对地址和入口签名。先校验磁盘程序，再校验进程路径、架构和入口字节。其他版本应重新调查与验证，直接改哈希或地址没有兼容保证。特殊窗口走不同函数时需要另外适配。

## 阅读与发布

列表采用 Qt model/view，最多保留最近 2,000 条，完整记录持续保存在文件中。向上滚动后保留阅读位置和选择，仅更新新增提示；复制和导出使用原始正文，不使用列表摘要。演示模式使用原创文字，不连接游戏。

搜索按人物名或正文匹配，输入防抖 150 ms，结果指向原列表而不隐藏上下文；新增和裁剪后维护当前匹配记录。搜索时暂停自动跟随，明确返回最新后恢复。正文高亮不修改原始记录和复制内容。

时间的原始值保留在记录与 JSONL 中；详情和列表共用格式化函数，分别显示日期加时钟与简短时钟，精确到秒。文件名使用 Windows 可用的日期和时分秒；同秒重名时用独占创建重试并追加编号，避免覆盖现有 TXT 或 JSONL。

纯启动由 `src/game.py` 校验主程序并使用独立工作线程调用 `Popen([executable], cwd=游戏目录, shell=False)`。组合入口由 `CaptureService(..., launch_game=True)` 使用 Frida 创建暂停进程，依次 attach、加载 agent、resume；失败或取消也会尝试恢复已创建的进程，不终止用户游戏。已运行时只连接现有游戏，退出后等待手动重新启动。

组合入口在 agent 就绪后调用 `src/speed_gear.py`，按相邻目录定位并校验 GearNT 0.46 三个文件的哈希，复用或启动管理进程。`src/gear_agent.js` 调用 SDK 导出的 `AddProcess(HANDLE)`、`SetSpeed(int)`、`GetSpeed()`；x86 使用 `mscdecl`，速度码 10 对应 `2 ** (10 / 10) = 2`。加入前通过打开的 HANDLE 重新核对游戏路径，句柄在 finally 中关闭；已有正确 DLL 时不重复注入。

SDK 采用共享倍率。更改前只读检查其他可枚举进程的模块，发现齿轮 DLL 冲突则保留原倍率；已经是码 10 时不重复写入。设置后从游戏回读 DLL 路径和速度码，而非仅相信管理端成功。第三方原生调用可能无响应，因此使用带请求编号的 `recv/send` 消息桥与宿主有界队列等待；不用无法取消等待的 `exports_sync`。停止、超时和迟到回复分别处理，清理也设取消期限。停止时先断开采集，再保存当前会话中已排队的对白，关闭文件后才报告保存完成。变速失败不会终止对白采集，提示随对白状态持续保留。

PyInstaller 构建为 `onedir`，Qt、Python 和 Frida 随 `_internal` 一起分发，不依赖接收者安装 Python。源码 ZIP 使用允许清单，排除个人路径设置、游戏、诊断、对白记录及开发环境。第三方许可证通过已校验的本地缓存离线收集，来源见 `scripts/licenses/SOURCES.json`。
