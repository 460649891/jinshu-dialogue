# 游戏版本兼容与适配

## 已适配版本

| 项目 | 当前范围 |
| --- | --- |
| 游戏 | 金书红颜录 5.60C |
| profile | `profiles/jshyl-5.60c.json` |
| 游戏进程 | x86 / `jshyl5.exe` |
| 主程序 SHA-256 | `e4648b2055cc09edd6166e29095bfeed7e576c09c5e11d77c7dacda81235521e` |
| 工具运行平台 | Windows x64，具体系统要求见 README |
| 采集对象 | 标准人物对白；无姓名时标记为“未知人物” |

5.60C 这个版本名不能单独证明兼容，同名主程序也可能不同。选择游戏时校验完整文件哈希，连接后继续检查进程路径、架构和入口签名。请保留这些保护。

游戏已显示的旧对白可能没有经过新安装的调用钩子，因此从下一句开始验证。菜单、战斗提示和不同类型的剧情窗口可能走其他函数，不在完整性承诺范围内。

## 请求适配

提交 Issue 时提供游戏版本说明、主程序 SHA-256、窗口类型及期望行为，不上传游戏文件或存档。PowerShell 可以计算哈希：

```powershell
Get-FileHash -LiteralPath '游戏目录\jshyl5.exe' -Algorithm SHA256
```

## 增加 profile

1. 在自己合法持有的游戏副本上调查真正的对白生命周期、对象归属和字符串布局；不能只寻找一段看起来相似的字节。
2. 将哈希、函数 RVA、调用返回位置和入口签名放入新的 `profiles/*.json`。RVA 是相对模块基址的地址，不能直接照搬其他版本的绝对地址。
3. 确认姓名和正文来自同一次对白、同一对象，处理无姓名、嵌套与重连。去重应区分重绘和下一次真实对白，即使文字完全相同。
4. 用原创事件补充行为测试，再实机核对多个角色、连续同名、连续同文、旁白、菜单误采、停止和重连。
5. PR 记录实际验证的场景、数量与限制，更新本页和 CHANGELOG。无法构造的场景明确标为未验证。

源码中已有的生命周期测试检查去重和配对规则；它们不证明任意游戏版本的函数地址正确。
