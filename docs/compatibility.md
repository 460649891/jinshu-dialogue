# 游戏版本兼容与适配

## 已适配版本

| 项目 | 当前范围 |
| --- | --- |
| 游戏 | 金书红颜录 5.60C |
| profile | `profiles/jshyl-5.60c.json` |
| 游戏进程 | x86 / `jshyl5.exe` |
| 主程序 SHA-256 | `e4648b2055cc09edd6166e29095bfeed7e576c09c5e11d77c7dacda81235521e` |
| 工具运行平台 | Windows x64，具体系统要求见 README |
| 采集对象 | 标准人物对白；无姓名时标记为“未知人物” |

5.60C 这个版本名不能单独证明兼容，同名主程序也可能不同。选择游戏时校验完整文件哈希，连接后继续检查进程路径、架构和入口签名。请保留这些保护。

游戏已显示的旧对白可能没有经过新安装的调用钩子，因此从下一句开始验证。菜单、战斗提示和不同类型的剧情窗口可能走其他函数，不在完整性承诺范围内。

## 可选变速齿轮

v0.4.0 的组合启动适配游戏旁的 GearNT 0.46 x86；文件哈希独立记录于 `assets/gearnt-0.46.json`，不与游戏 profile 混用。当前已验证首次加入独立 x86 测试进程、复用游戏中已有的 DLL、从游戏读回速度码，以及相对于宿主时钟约 2.0 倍的实际计时。其他齿轮版本需重新核实导出接口、调用约定和速度码，不能只替换文件名或跳过哈希。

第三方 EXE / DLL 不进入源码包和免安装包。齿轮不可用时，普通对白采集仍可使用。

## 请求适配

提交 Issue 时提供游戏版本说明、主程序 SHA-256、窗口类型及期望行为，不上传游戏文件或存档。PowerShell 可以计算哈希：

```powershell
Get-FileHash -LiteralPath '游戏目录\jshyl5.exe' -Algorithm SHA256
```

## 增加 profile

1. 在自己合法持有的游戏副本上调查真正的对白生命周期、对象归属和字符串布局；不能只寻找一段看起来相似的字节。
2. 将哈希、赋值函数和正文提交 RVA、对象偏移、姓名表与解码参数、位置签名放入新的 `profiles/*.json`。RVA 是相对模块基址的地址，不能直接照搬其他版本的绝对地址。
3. 确认姓名和正文来自同一次提交、同一对象，处理无姓名、大编号角色与重连。去重应区分重绘和下一次真实对白，即使文字完全相同。姓名表数量与其他相邻表数量不可混用。
4. 用原创事件补充行为测试，再实机核对多个角色、连续同名、连续同文、旁白、菜单误采、停止和重连。
5. PR 记录实际验证的场景、数量与限制，更新本页和 CHANGELOG。无法构造的场景明确标为未验证。

v0.3.0 已在上述版本实机采集多人物连续对白，包括编号大于 934 的角色，并将当前画面与 TXT 配对核对。自动测试另覆盖 1,000 次快速切换、无姓名和连续同文；这些测试不能证明所有剧情窗口或其他版本的地址正确。
